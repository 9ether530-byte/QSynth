QSYNTH
How it works Verification API Workbench

Classical specifications, compiled to quantum circuits that have been checked.

Write a Boolean expression, a truth table, or a function in a Python subset. QSYNTH lowers it through a reversible circuit to Clifford+T and emits OpenQASM 3.0 — and will not hand you the result until it has proved the circuit computes what you wrote.

Open the workbench Read the API

Up to 12 inputs, equivalence is checked on every input assignment — 4096 of 4096, not a sample. Above that the report states the sample count and the seed that produced it, so you can tell the two apart at a glance.

Four layers, each one inspectable

Nothing between your specification and the emitted circuit is a black box. Every layer is stored and can be read back, including the ancilla ledger that records why each helper qubit was allocated and where it was uncomputed.

01

Classical IR

Your specification as a typed SSA dataflow graph, with source spans preserved.

02

Reversible IR

Bennett embedding over NOT, CNOT and Toffoli. Compute, copy out, uncompute — so freedom from garbage is structural rather than a later repair.

03

Quantum IR

Clifford+T decomposition by rules each verified once against their exact unitary, with T-count and T-depth reported.

04

OpenQASM 3.0

Deterministic output: the same specification compiles to the same bytes, every time.

Six checks stand between a circuit and an export

The gate is enforced on the server, against the stored report for those exact bytes. It is not a disabled button — an owner with a valid API key gets the same refusal, because the check is on the artifact, not on the caller.

Check What it establishes
type_shape Inputs and outputs have the arity and width your specification declared.
simulation_equivalence The circuit agrees with your specification on every input assignment, exhaustively up to 12 inputs; above that, on a stated number of seeded samples.
reversibility Every gate permutes basis states, so the circuit can be run backwards.
garbage_free Every ancilla returns to zero on every input. A leaked ancilla is a failed check.
property Assertions declared alongside the specification hold across the input space.
resource Qubits, depth, gate count and T-count fit the budget you sent with the request.

A failing check reports a counterexample: the inputs, what your specification says, and what the circuit did. A check that was never reached is reported as not reached — which is a different thing from a check that ran and found nothing to do, and the report says which.

Everything the workbench does, the API does

The interface is a client of the same REST API you get an API key for. Compile, verify, diff and export are all plain requests.

Compile and verify

curl -X POST "$QSYNTH/v1/compile" \
  -H "Authorization: Bearer $QSYNTH_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{
    "projectId": "…",
    "kind": "boolean",
    "source": "out = (a AND b) XOR c",
    "budget": { "maxQubits": 8 }
  }'

What comes back

{
  "job": { "status": "succeeded",
           "seed": 3248988783, … },
  "verification": {
    "passed": true,
    "stoppedAt": null,
    "checksReached": ["type_shape",
      "simulation_equivalence", … ],
    "checks": [{
      "id": "simulation_equivalence",
      "status": "passed",
      "coverage": { "mode": "exhaustive",
                    "checked": 8, "space": 8 }
    }, … ]
  },
  "resources": { "measured": { "qubits": 6, … },
                 "cliffordT": { "tCount": 14, … } },
  "artifacts": [ { "kind": "qasm3", "id": "…" },
                 { "kind": "reversible_ir", … }, … ]
}

Errors come back in one envelope: a machine-readable code, a message, a hint, and retryable. The whole table is published at GET /v1/errors, so a client can generate its own enum and retry policy from the API it is actually talking to rather than from a copy that ages. The rate-limit budget is reported on every response, not only on the one that is refused.

What it does not do

Said here, because finding out later is worse.

no Arbitrary Python. The subset is a whitelist — bounded integers, Boolean and comparison operators, if/else, and for over literal ranges. Anything else is refused by name, with the line, and a list of what is supported.
no Hardware execution. QSYNTH emits OpenQASM 3.0 and resource estimates; running that on a device or a vendor simulator is your next step, not ours.
no Speedup claims. Compiling a classical function to a reversible circuit gives you an oracle, correctly built and measured. Whether an algorithm around it beats a classical one is a question about that algorithm.
yes Exhaustive equivalence up to 12 inputs, a counterexample when it fails, and an export gate that cannot be talked out of it.
